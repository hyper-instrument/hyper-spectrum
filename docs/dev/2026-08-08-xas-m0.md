## Integrated Zenodo XANES adapter (not 5090 success evidence)

The public Zenodo record `10606662`, version `1.0.0`, revision `4`, is now
supported by `hyperspectrum data materialize-xanes-spec`. This code-path smoke
was run locally against the 3.75 MB public archive only; it is not a substitute
for the still-blocked authenticated 5090 selection/run evidence above.

The real source inventory contains 495 files: 490 `.dat` spectrum candidates,
four extensionless motor scans, and one `experimental_conditions.txt` sidecar.
Strict parsing admitted 472 spectra and rejected 18 empty/short scans into QC.
The fixed composition split contains 298 train, 28 validation, and 146 test
samples. The reference is the real non-uniform 135-point energy grid from the
first path-sorted admitted train file,
`Exp2_La05_heating_500_000_000.dat`; test and validation data cannot select it.

The upstream integrity audit reports 444 declared-size disagreements while all
495 declared SHA-256 values match. The materializer therefore records size drift
without treating it as byte corruption, but aborts the entire run on any SHA
mismatch, missing file, unexpected file, or symlink. The local archive smoke used
an actual-size declaration and therefore observed zero size drift; it did not
invent upstream size metadata.

Noise is deterministic count-channel Binomial thinning with configurable dose
(default 0.25) and an order-independent per-sample seed. The target is always
named `pseudo-clean frozen measurement` with
`is_physical_noiseless_ground_truth: false`. Two identical real-source runs
produced byte-identical canonical NPZ assets. No benchmark asset or temporary
source declaration is committed to this repository.

Independent review hardening now parses every source file from the exact byte
snapshot that was hashed, bounds endpoint clamping to 0.05 eV, and reads the
derived asset once before both hashing and loading. Planning validates the full
materializer manifest, recomputes both source identity chains, binds the
declared-manifest digest to the catalog candidate, and reserves five-key NPZ
execution for legacy v2 plans; v3 accepts only the canonical 16-key asset.

## Evidence contract prepared for recovery

`docs/evidence/xas-m0-selection.schema.json` remains the frozen v1 success-only
handoff contract. The new
`docs/evidence/xas-m0-selection-v2.schema.json` is the default for explicit
benchmark assets. Both exact schemas ship inside the wheel, and
`hyperspectrum evidence validate` dispatches by `schema_version` before applying
semantic checks. v2 requires, among other fields:

- a non-null real dataset version and non-zero content digest;
- declared license/access, source, file/sample/split counts, ground-truth roles,
  and split-group keys;
- an exact asset ID, role, file name, byte size, SHA-256, byte provenance,
  semantics, and ACE-compatible `mount-file | mount-dir | unpack`
  materialization with its `inner_path` rule;
- deterministic sample-selection algorithm/version and ordered sample-set digest;
- complete plan/model/tool/implementation/weight/environment provenance plus
  separate source-dataset, verified-content-manifest, and benchmark-asset
  SHA-256 values, a `hyperspectrum-prediction/v3` claim, and prediction/run
  manifest digests;
- one named ACE data asset whose ID and benchmark SHA-256 match the derived NPZ,
  while each source digest matches only its own catalog/byte/execution chain;
- ordered dataset, parsed-file, full-split, selected, input, and prediction
  counts; and
- zero unresolved blockers and no secret, signed URL, or private-path fields.

Run plans now bind the exact ordered sample IDs under selection policy
`explicit_order` version `1` in `hyperspectrum-run-plan/v3`. Reordering or
replacing a sample changes the plan digest and therefore the run ID; the
executor rejects a supplied selection that does not exactly match the plan.
Unbound v1 plan files are refused rather than guessed. Plan/prediction v2 remain
readable and executable only for existing artifacts. New planning/writing uses
v3 and validates NPZ bytes only against `benchmark_asset_digest`.

## Recovery procedure

After operators restore the Hub, run these bounded commands through the approved
task-scoped environment:

```bash
hyd --profile volcano whoami
hyperspectrum doctor --json
hyperspectrum data discover --modality xas --profile volcano --json
hyperspectrum tools match --task xas-denoising --json
```

Proceed only if `whoami` explicitly confirms the identity with the selected
server and discovery returns a fresh supported JSON envelope. Then:

1. Select only a real candidate with non-null version/digest and explicit
   ground-truth, pairing, and split evidence.
2. Create a complete `hyperspectrum-xanes-source-declaration/v1` JSON object
   containing explicit dataset id/code/version, `upstream_revision` (a real
   value, `"unknown"`, or `null`), the full declared-manifest SHA-256, expected
   file count, and one `{path, size, sha256}` entry per source file.
3. Run `hyperspectrum data materialize-xanes-spec --source-root SOURCE_DIR
   --source-declaration-file DECLARATION.json --output-directory BENCHMARK_DIR
   --dose-fraction 0.25 --global-seed SEED --json`. Review `qc.json`,
   `split.json`, and `manifest.json`; stop on any source-integrity error.
4. Create a plan with `--benchmark-manifest-file BENCHMARK_DIR/manifest.json`,
   repeated `--sample-id` options in deterministic order, maximum eight samples,
   and execute the identical ordered selection locally.
5. Generate `xas-m0-selection.json` only after every success field is observed
   and `hyperspectrum evidence validate --evidence-file
   xas-m0-selection.json --json` succeeds. Formal scoring remains owned by ACE
   Benchmark.
